# 관리자 대시보드 최종 구현 기록

> 이후 적용한 ERP 방식의 업무 탭·메뉴 트리는 [탐색 구조 개선 기록](ERP-NAVIGATION.md)에 정리했다.

검증 주소: `http://localhost:3001/admin`. 격리된 로컬 DB와 콘솔 문자 공급자로 실행했다. 실제 데이터 화면에서는 조회·확인창 열기·취소만 수행했으며, 배정 성공과 오류 처리는 API를 모킹해 검증했다.

## 디자인과 동작

| 영역 | 구현 |
| --- | --- |
| 전체 인상 | 차콜 `#232628` 사이드바, 아이보리 `#F6F5F1` 바탕, 흰 작업 영역, 전기 서비스의 노랑 `#F1CA50`을 사용한다. 큰 장식 배너 대신 목록과 배정 작업에 공간을 배분했다. |
| 공통 메뉴 | 1280px 이상에서 184px 사이드바를 표시한다. 작은 화면에서는 56px 헤더와 메뉴 서랍을 사용한다. 분석 하위의 현황·지도·설문·평점, 정산 집계를 포함한 모든 관리자 목적지에 접근할 수 있다. |
| 상단 | 간결한 제목·갱신 시각·새로고침과 약 80px 높이의 요약 영역을 배치한다. 관리자 확인·배정 대기·진행 중·긴급 미완료를 보여주고 각각 목록 필터나 분석 화면으로 연결한다. |
| 목록 | 접수 내용·고객·진행 상태·접수 시각의 4열이다. 1440×1000 기본 화면에서 첫 접수는 상단 300px 이내에 시작한다. 일반적인 내용 길이에서는 약 5~7개 행을 한눈에 볼 수 있다. |
| 긴 내용 | 내용은 2줄, 주소는 1줄 미리보기로 제공하고 넘칠 때만 `내용 펼치기`를 표시한다. 펼치면 원문 전체를 보여준다. 자동 갱신 후에도 펼침 상태를 유지한다. |
| 상세 | 1440px 이상에서는 420px 상세 패널을 목록 옆에 표시한다. 목록과 상세 내용이 독립적으로 스크롤된다. 768~1439px에서는 최대 480px 모달, 더 작은 화면에서는 전체 화면 모달이다. |
| 상세 조작 | 화면 너비가 바뀌어도 상세 컴포넌트를 중복 마운트하지 않는다. Tab 순환·Escape·배경 조작 차단·닫은 뒤 선택 버튼으로 초점 복귀를 제공한다. 중첩 배정 확인창의 Escape는 확인창만 닫는다. |
| 배정 | 첫 후보의 배정 버튼을 노란색으로 강조한다. 기존 후보 조회·배정 요청·충돌 처리·중복 요청 방지 동작을 유지했다. 조회 오류가 있으면 재시도 전 배정을 막는다. |
| 공통 프레임 범위 | 다른 관리자 화면은 메뉴와 바깥 프레임을 공유한다. 로그인과 계약서 인쇄에는 관리자 프레임을 표시하지 않는다. 다른 분석 페이지 본문까지 재설계한 변경은 아니다. |

## 검증 체크리스트

- [x] 4열 목록, 긴 이름·내용·주소, 전화 링크, 명시적인 펼치기/접기
- [x] 검색·상태 필터·정렬·25건 페이지 이동·필터 변경 시 첫 페이지 복귀
- [x] 요약 기준 표시, 요약 클릭 이동, 기존 8초 자동 갱신
- [x] 갱신 후 펼침 유지, 상세를 닫은 뒤 읽던 행의 위치 및 초점 복귀
- [x] 선택 전 후보 미조회, 선택 시 단일 조회, 빠른 선택 변경 시 이전 후보 제거
- [x] 접수/후보 조회 오류 구분, 재시도, 오류 중 배정 차단
- [x] 배정 요청 형식 유지, 확인 취소 시 미전송, 중복 클릭 시 한 번만 요청
- [x] 배정 충돌 메시지, 성공 후 목록 갱신
- [x] 데스크톱 상세 Escape, 모바일 상세 및 중첩 확인창의 키보드 동작
- [x] 관리자 메뉴 11개 목적지 이동, 현재 위치 표시, 분석 펼치기/접기
- [x] 320/390/768/1024px 메뉴 서랍의 초점 순환·배경 잠금·이동·닫기
- [x] 계약서 인쇄 CSS, 인쇄 전용 경로 및 로그인 프레임 제외
- [x] 설문 목록의 고객 입력 금액·0원·미입력·응답일 및 지도 메뉴 회귀 검증
- [x] 목록과 상세 각각 7개 너비(320~1920px)에서 가로 넘침 없음
- [x] 위 화면들과 모바일 메뉴의 axe WCAG A/AA 자동 검사 위반 없음
- [x] 실제 로컬 데이터의 배정 후보·완료 접수·고객 설문 표시 확인
- [x] 브라우저 JavaScript 오류 없음, 실제 배정 요청 전송 없음
- [x] 프로덕션 빌드·TypeScript·변경 소스 ESLint·diff 공백 검사 통과

관련 Playwright 항목은 총 30개를 통과했다. 메인/요약/공통 메뉴 테스트 중 21개가 먼저 통과했고, 레이아웃 전환에 맞춰 테스트의 화면 너비와 확인창 선택자를 수정한 뒤 배정 8개·목록 위치 1개·설문/지도 2개를 통과했다(중복 2개 제외). 두 번째 실행 결과는 [Playwright 기록](command-center-evidence/playwright-regression.json)에 보관했다.

자동 접근성 검사 결과는 완전한 수동 접근성 인증을 뜻하지 않는다. 목록 API의 기존 최대 200건, 페이지당 25건 정책은 유지된다. 검색과 필터는 조회된 200건 안에서 동작한다. 전체 요약을 조회하지 않는 작은 화면에서는 조회된 접수 기준 수치를 표시하며, 진행 중 수치는 모든 화면에서 조회된 접수 기준이다. 이번 변경은 API·DB 스키마·마이그레이션을 추가하지 않았다.

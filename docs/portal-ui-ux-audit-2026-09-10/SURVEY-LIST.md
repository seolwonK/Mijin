# 관리자 전체 설문 목록 개선

2026-09-10 · 확인 경로: http://localhost:3001/admin/analytics/surveys

## 변경한 동작

기존 화면은 미제출 설문을 최대 50건만 보여 주었다. 이제 생성된 모든 설문을 최신 생성순으로 조회하고, 전체·응답 완료·미응답 필터와 검색으로 범위를 좁힐 수 있다.

| 기능 | 동작 |
| --- | --- |
| 첫 진입 | 전체 설문 표시 |
| 상태 필터 | 제출 일시가 있으면 응답 완료, 없으면 미응답 |
| 고객 입력 금액 | 각 설문의 paidAmount 원화 표시. 금액을 재계산하거나 수정하지 않음 |
| 입력 상태 구분 | 0원은 `0원`, 응답했지만 금액을 비웠으면 `금액 미입력`, 미응답이면 `—` |
| 추가 정보 | 접수번호·고객명·전화번호·평점·설문 생성일·응답일·미응답 경과일 |
| 상세 내용 | 접수번호를 누르면 기존 접수 상세에서 후기와 상세 정보 확인 |
| 검색 | 접수번호·고객명·전화번호. 하이픈을 포함한 전화번호도 검색 가능 |
| 페이지 이동 | 50건씩 이전·다음 이동, 전체 건수·현재 범위 표시 |
| 필터·검색 변경 | 첫 페이지로 이동. 새 응답이 오기 전 이전 조건의 결과를 표시하지 않음 |
| 상단 요약 | 전체 기간 기준 전체·응답 완료·미응답 수, 응답률, 고객 입력 금액 합계·입력 건수·평균 |
| 모바일 | 데스크톱 제한을 제거하고 목록으로 표시. 같은 필터·검색·페이지 이동 제공 |
| 오류 | 빈 목록과 통신 실패를 구분하고 재시도 제공. 갱신 실패 시 마지막 조회 결과임을 표시 |

금액은 **고객이 설문에 적은 지불 금액**이며 업체 정산 확정액이 아니다. 기존 수수료 요율·장부·금액 데이터를 변경하지 않았다. '발송 건수'라는 기존 표현은 '전체 설문'으로 바로잡았다.

## API

`GET /api/admin/analytics/surveys?status=ALL&page=1&q=...`

- 관리자 인증 필요. status는 ALL / SUBMITTED / PENDING, page는 양의 정수, q는 최대 100자.
- 목록 응답은 `surveys.items`, `surveys.total`, `page`, `pageSize`, `pageCount`, `hasNext`를 포함한다.
- 상단 요약은 전체 기준, 목록의 건수와 항목은 동일한 상태·검색 조건을 적용한다.
- 요청 페이지가 마지막 페이지를 넘어가면 마지막 페이지로 보정한다.
- 설문 토큰은 응답에 포함하지 않는다. GET은 데이터 변경이나 문자 발송을 수행하지 않는다.
- 스키마 변경이나 마이그레이션 없이 기존 SatisfactionSurvey 필드를 사용한다.

## 검증

- Playwright 16개 관련 시나리오 통과: 목록·금액·0원·미입력, 필터·검색·페이지 초기화, 모바일, 오류·지연 응답, 관리자 권한, 잘못된 조회 조건, 기존 분석 API 응답 계약.
- 실제 테스트 DB에 54건을 생성해 50+4건의 페이지 이동, 중복·누락 없음, 완료·미응답 각 27건, 접수번호·전화번호 검색을 확인했다. 테스트가 만든 접수·설문은 종료 후 정리했다.
- Vitest 4개 통과: 빈 데이터, 전체 요약과 필터 건수 구분, 마지막 페이지 보정, 0원과 미입력 구분.
- TypeScript·변경 파일 ESLint·프로덕션 빌드 통과.
- 실제 관리자 계정으로 전체·완료·미응답을 전환하고 API 금액과 화면을 대조했다.
- 320/390/768/1023/1440px에서 가로 넘침 없음, axe 접근성 검사 위반 0건, 브라우저 JS 오류 0건을 확인했다.
- 화면 증거와 브라우저 검증 결과: `survey-evidence/`.

수정 파일: `src/lib/surveyAnalytics.ts`, `src/app/api/admin/analytics/surveys/route.ts`, `src/components/AnalyticsSurveys.tsx` 및 관련 테스트.

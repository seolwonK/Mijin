# ERP 업무 탐색과 탭

기존 차콜·아이보리·노랑 디자인에 ERP 방식의 업무 트리와 열린 화면 탭을 적용했다. 로컬 확인 주소는 `http://localhost:3001/admin`이다.

## 변경 내용

| 영역 | 동작 |
| --- | --- |
| 업무 메뉴 | 접수 운영·파트너 관리·정산·분석·시스템 그룹을 접고 펼치는 트리로 구성했다. 검색은 그룹과 메뉴 이름을 함께 대상으로 한다. 메뉴 이동 후 검색어는 초기화하고, 다른 그룹의 접힘 상태는 유지한다. |
| 업무 탭 | 방문한 관리자 화면을 상단 탭으로 추가한다. 같은 경로는 중복 생성하지 않으며 대시보드는 고정한다. 쿼리 문자열과 URL의 해시를 포함한 주소를 기억한다. |
| 닫기 | 비활성 탭을 닫으면 현재 화면을 유지한다. 현재 탭을 닫으면 왼쪽 인접 탭으로 이동한다. 열린 업무 목록에서 대시보드와 현재 화면을 남기고 다른 탭을 닫을 수 있다. |
| 복원 | 같은 브라우저 탭의 새로고침에서 열린 업무 목록과 주소를 복원한다. 로그인 화면에 들어가면 초기화한다. 외부 주소·로그인·인쇄 경로와 손상된 저장 데이터는 복원하지 않는다. |
| 공간 | 데스크톱에서는 왼쪽 메뉴 전체를 접어 본문을 넓힐 수 있다. 상단 업무 바는 40px이며, 목록 상단 간격을 조정해 1440×1000에서 첫 접수가 여전히 300px 이내에 시작한다. |
| 모바일 | 기존 메뉴 서랍을 유지한다. 업무 탭은 가로 스크롤과 열린 업무 목록으로 전환하며, 선택한 탭 전체가 보이는 위치로 이동한다. |
| 키보드 | 업무 탭 링크에서 좌우 방향키와 Home/End로 초점을 이동하고 Enter로 연다. Delete로 탭을 닫는다. 브라우저의 조합키는 가로채지 않는다. 목록 팝오버는 Escape와 바깥 클릭으로 닫힌다. |
| 상태 필터 | 본문 안의 접수 상태 필터도 작은 탭 형태로 정리했다. 상단 업무 전환 탭과 구분되는 노란 선택 배경을 사용하며, 모바일에서는 한 줄로 가로 스크롤한다. |
| 인쇄 | 메뉴·업무 탭·여백을 숨긴다. 계약서 인쇄 전용 경로와 로그인에서는 프레임 전체를 생략한다. |

탭은 기존 Next.js 경로를 오가는 탐색 구조다. 열린 목록과 주소를 보존하며, 모든 페이지의 미저장 폼이나 내부 상태를 메모리에 보관하는 MDI 창 관리 기능은 추가하지 않았다. 숨겨진 페이지를 계속 실행하거나 API 폴링을 중복으로 늘리지 않는다. 별도 Nexacro 라이브러리는 도입하지 않았다.

## 검증

- [x] 탭 중복 방지·새로고침 복원·직접 주소·뒤로가기·쿼리 문자열 유지
- [x] 현재/비활성 탭 닫기·대시보드 고정·초점 복귀·다른 탭 닫기
- [x] 방향키·Home/End·Delete·Escape
- [x] 메뉴 검색·빈 결과·검색 초기화·트리 접힘 유지·사이드바 접기
- [x] 320/390/768/1280px에서 탭이 많아도 가로 넘침 없음, 활성 탭 전체 노출
- [x] 손상된 세션 데이터·외부 주소 제외, 로그인 시 목록 초기화
- [x] 공통 메뉴의 모든 목적지 이동·모바일 서랍·인쇄 제외 회귀 검사
- [x] 접수 요약 폴링·검색·필터·상세·배정 확인창 동작 회귀 검사
- [x] 첫 접수 위치·내용 펼침 유지·상세를 닫은 뒤 읽던 행의 위치 유지
- [x] 실제 로컬 데이터로 목록과 상세 각각 7개 너비(320~1920px)의 가로 넘침 및 axe WCAG A/AA 자동 검사 통과
- [x] 모바일 메뉴 자동 접근성 검사 통과, 브라우저 JavaScript 오류 없음
- [x] 프로덕션 빌드·TypeScript·변경 소스 ESLint·diff 공백 검사 통과

관련 Playwright 항목 총 29개를 확인했다. 첫 실행에서 28개를 통과했고, 첫 행 위치의 소수점 차이를 여백 조정으로 해결했다. 최종 실행에서는 위치 검사와 새 업무 탭 관련 10개를 모두 통과했다. [첫 실행](erp-navigation-evidence/playwright-initial.json), [최종 실행](erp-navigation-evidence/playwright-final.json), [화면/접근성 결과](erp-navigation-evidence/verification.json)를 보관했다.

검증에는 격리 DB와 콘솔 문자 공급자를 사용했다. 실제 배정·문자 발송 없이 조회 및 확인창 취소를 확인했다. 자동 접근성 검사는 완전한 수동 접근성 인증을 뜻하지 않는다.

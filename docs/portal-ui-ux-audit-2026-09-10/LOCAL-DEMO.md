# 로컬 테스트 계정

업체·전기기사 화면을 직접 확인할 수 있는 전용 로컬 환경입니다.

| 구분 | 로그인 주소 | 아이디 | 비밀번호 |
| --- | --- | --- | --- |
| 업체 | http://localhost:3001/partner/login | `test_partner` | `Test1234!` |
| 전기기사 | http://localhost:3001/tech/login | `test_tech` | `Test1234!` |

두 계정 모두 가입 승인 상태입니다. 기사 계정에는 화면 확인용 확정 계약서와 테스트 서명을 넣었습니다.

각 계정의 초기 데이터:

- 배정 30건: 응답 대기 2건, 수락 1건, 출동 중 1건, 완료 22건, 거절 2건, 취소 1건, 기한 만료 1건
- 고객 후기 21건, 미응답 만족도 조사 1건
- 고장 유형별 예시 첨부 이미지
- 알 잔액 16개: 테스트 충전 40개에서 수락 이력 24건 차감
- 추천 업체 1곳, 소개 수수료 6건: 적립 대기 9,000원, 지급 완료 20,000원
- 추천 업체의 만족도 조사 대기 1건

응답 대기 건에는 기존 10분 만료 규칙이 적용됩니다. 직접 수락·출동·완료하거나 시간이 지나면 표시되는 상태와 건수가 달라집니다. 같은 브라우저에서 계정을 바꿀 때는 로그아웃 후 로그인합니다.

## 실행 환경

- 실행 디렉터리: `/tmp/mijin-portal-audit`
- 전용 PostgreSQL 데이터베이스: `mijin_portal_audit_20260910`
- 문자: `console` (실제 문자 발송 없음)
- 본인인증: `mock`
- 파일 저장: 전용 데이터베이스
- 자동 배정: 비활성화. 기존 응답 기한 만료 처리는 정상 작동합니다.

서버가 종료된 경우 다음 명령으로 다시 실행합니다. 현재 소스의 프로덕션 빌드가 준비되어 있습니다.

```sh
cd /tmp/mijin-portal-audit
ALLOW_MOCK_IDENTITY=1 npm run start -- --port 3001
```

계정 생성 스크립트는 실행 디렉터리의 `seed-demo.ts`, 검증 스크립트는 `verify-demo.cjs`입니다. 생성 스크립트는 지정된 로컬 DB와 mock 설정을 확인하며, 계정이 이미 있으면 기존 작업을 보존하고 중단합니다.

## 검증

두 계정의 실제 로그인, 작업·후기·알·추천·수수료·프로필 API, 기사 계약서 API, 이력 페이지 이동·상태 필터·검색, 첨부 이미지 표시·확대, 모바일 390px·PC 1440px 화면을 확인했습니다. 로그인 및 화면 확인 중 브라우저 JavaScript 오류가 없었습니다.

상세 검증 결과와 화면 캡처: `/tmp/mijin-portal-audit/demo-evidence/`

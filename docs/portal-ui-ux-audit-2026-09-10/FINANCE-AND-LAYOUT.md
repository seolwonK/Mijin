# 정산 원본 조회 · 설문 재발송 · 관리자 레이아웃 점검

2026-09-10. 관리자 업무 화면을 대상으로 기능 및 화면 구성을 점검하고 수정했다.

## 반영한 기능

### 정산 집계

- 업체/전기기사의 이름 또는 신고 금액을 누르면 해당 대상·해당 월의 상세 패널을 연다.
- 각 원본에 접수번호, 작업 주소, 접수 내용, 신고 고객명, 고객 입력 금액, 설문 응답 시각(KST), 평점을 표시한다.
- 접수번호에서 접수 상세로, 대상 정보 링크에서 업체/기사 관리로 이동한다.
- 월 귀속은 작업 완료일이 아닌 **설문 응답일**이다. 기존 집계와 동일한 KST 월 경계를 사용한다.
- 0원과 금액 미입력을 구분한다. 금액 미입력 설문은 응답 건수에 포함하고 합계에서 제외한다.
- 기존 집계 대상 기준을 유지한다. 해당 월에 금액을 입력한 설문이 하나도 없는 대상은 집계 표에 나타나지 않는다. 미응답 설문은 설문 화면에서 관리한다.
- 원본은 25건씩 조회한다. 합계와 건수는 해당 월 전체를 기준으로 표시한다. 같은 응답 시각은 ID로 안정적으로 정렬한다.
- 오류·재시도·빈 결과·대상 변경·월 변경·뒤늦은 응답을 처리한다.
- 상세는 데스크톱 최대 780px, 모바일 전체 폭이다. Escape·배경 클릭·닫기 및 원래 버튼으로 초점 복귀를 지원한다.
- CSV 내보내기는 기존의 월 전체 금액 입력 원본을 유지한다.

API: `GET /api/admin/settlements?month=YYYY-MM&kind=PROVIDER|TECHNICIAN&payeeId=...&page=1`.
관리자만 조회 가능하며 잘못된 대상 구분/페이지는 400, 없는 대상은 404이다. 개인정보 응답은 `no-store`로 제공한다.

### 설문 재발송

- 전체/미응답 목록의 **미응답 설문에만** 재발송 버튼을 제공한다.
- 확인창에서 접수번호·고객명·수신 번호를 확인한 뒤 발송한다. 취소는 발송하지 않는다.
- 기존 설문 토큰을 사용한다. 새 설문 생성, 토큰 교체, 기존 응답·신고 금액 수정은 하지 않는다.
- 서버에서 응답 완료 여부를 다시 확인하고 완료된 설문에는 409를 반환한다.
- 설문별 PostgreSQL 트랜잭션 잠금과 발송 로그 예약으로 동시 관리자 요청을 직렬화한다. 외부 문자 요청은 트랜잭션을 끝낸 뒤 실행한다.
- 같은 설문은 최근 발송 시도로부터 60초 후 재발송할 수 있다. 제한 시 429와 `Retry-After`를 제공한다.
- 발송 요청 결과를 기다린 후 성공/실패를 구분한다. Solapi 오류는 502와 실패 로그로 남는다. 네트워크 대기는 20초로 제한한다.
- 목록에 마지막 발송 시각과 발송 요청 완료/실패/확인 중/테스트 발송을 표시한다. 서비스에 요청된 상태와 고객의 실제 문자 수신을 동일시하지 않는다.
- 콘솔 제공자를 사용하는 로컬 환경은 실제 문자를 보내지 않았다는 결과를 명시한다.

API: `POST /api/admin/analytics/surveys/[id]/resend`.
기존 `SmsLog`를 사용하며 이번 기능에 DB 마이그레이션은 필요하지 않다. 예약 중 로그 상태는 `PENDING`이다.

## 레이아웃 전수 점검 범위

관리자 업무 화면 18종 × 390/768/1280/1440/1920px = 90개 화면 조합을 비교했다. 관리자 로그인은 기존 내비게이션 회귀 테스트에서 프레임 제외 여부를 확인했다. 일반 고객 및 업체/기사 포털은 이번 전수 점검 범위에 포함하지 않았다.

| 화면 | 점검 및 조치 |
| --- | --- |
| 관리자 대시보드 | 기존 표/인스펙터, 업무 탭, 페이지 폭 유지 확인 |
| 순환 현황 | 지역 탐색과 모바일 목록, 공통 프레임 확인 |
| 업체 목록 | 표 및 모바일 목록, 공통 높이/배경 확인 |
| 전기기사 목록 | 표 및 모바일 목록, 공통 높이/배경 확인 |
| 소개 수수료 정산 | 표와 상세 화면, 업무 탭/콘텐츠 간격 확인 |
| 정산 집계 | 상단 금액 요약, 목록, 원본 패널, 모바일 배치 개선 |
| 분석 현황 | 모바일 차단 해제, 헤더 줄바꿈, 금액 지표 폭 자동 조정 |
| 전국 지도 | 모바일 차단 해제, 표 스크롤 영역 키보드 접근, 지도 영역 접근성 개선 |
| 설문 현황 | 날짜 열 통합, 재발송 열, 표 높이 제한·고정 머리글, 모바일 행동 버튼 |
| 평점 현황 | 모바일 차단 해제, 표 최소 폭 580px, 1440px 이상에서 360px 상세 패널 분리 |
| 설정 | 최대 1160px, 넓은 화면 두 열, 1100px 미만 한 열, 긴 설명·긴급도 글자 대비 개선 |
| 업체 등록 | 입력 폼 및 안내 폭 900px로 일치 |
| 기사 등록 | 입력 폼 및 안내 폭 900px로 일치 |
| 업체 상세 | 헤더·인증·소개자·수정 폼 폭 900px로 일치 |
| 기사 상세 | 헤더·인증·소개자·수정 폼 폭 900px로 일치 |
| 접수 상세 | 내용·후보 영역 및 스크롤 시 헤더 겹침 확인 |
| 기사 계약서 | 공통 헤더와 업무 탭 간격, 입력/서명 영역 확인 |
| 기사 계약서 인쇄 | 업무 프레임 제외 및 문서 폭 유지 확인 |

공통 수정:

- 페이지 높이를 업무 탭 높이를 뺀 뷰포트 기준으로 정리했다.
- 기존 고정 페이지 헤더가 업무 탭 뒤로 들어가지 않도록 상단 오프셋을 적용했다.
- 긴 페이지 제목의 줄바꿈을 허용하고 오른쪽 동작 영역의 폭을 유지했다.
- 상세 입력 폼은 읽기 적절한 최대 폭을 두고, 집계/조회 표는 가용 공간을 사용한다.
- 좁은 화면의 복잡한 지도/평점 표는 영역 내부에서 가로로 스크롤한다. 페이지 전체는 가로로 넘치지 않는다.

## 검증

- Next.js 프로덕션 빌드 및 TypeScript 통과.
- 변경 코드 ESLint 및 `git diff --check` 통과.
- Vitest 16개 통과: 기존 집계·설문 집계·설문 전달 및 신규 DB 기능 테스트.
- Playwright 기능 44개와 API 매트릭스·접근 권한 8개 통과: 정산 원본/재발송 10, 설문 6, 업무 탭 9, 내비게이션 7, 평점 5, 지도 7, 매트릭스 완전성 6, 분류/신규 재발송 권한 2.
- 최종 접근성 검사 21개 화면 상태에서 WCAG A/AA 위반 0건, 브라우저 JavaScript 오류 0건. 수정된 지도 역할·출처 링크와 정산 상세를 별도로 재검증했다.
- 신규 DB 테스트: KST 월 경계, 업체/기사 분리, 0원/미입력, 합계=원본 합산, 25건 이후 페이지, 없는 대상/빈 월, 동시 재발송, 완료된 설문 차단, 발송 실패와 재시도, API 권한/입력 검증.
- 실제 DB의 정산 원본과 설문 목록을 브라우저에서도 열어 확인했다.
- 레이아웃 90개 조합에서 페이지 가로 넘침 없음. 최종 접근성 결과와 스크린샷은 아래 파일 참조.

검증은 `mijin_portal_audit_20260910` 격리 DB와 `http://localhost:3001`에서 수행했다. 실제 고객 문자를 보내지 않았다. Solapi 실패/성공은 네트워크 모의 응답으로 확인했으며, 실제 통신사 수신까지 검증한 것은 아니다.

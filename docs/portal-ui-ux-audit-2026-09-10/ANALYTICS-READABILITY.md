# 분석 현황·지도 가독성 개선

2026-09-10 · 로컬 검증 http://localhost:3001

## 확인한 문제와 변경

| 기존 문제 | 적용한 변경 |
| --- | --- |
| 전체 기간의 현재 상태와 선택 기간의 실적이 같은 위계로 혼재 | 상단에 현재 남은 업무, 아래에 선택 기간 실적을 분리 |
| 일·주·월의 실제 범위를 추측해야 함 | 오늘 / 최근 7일 / 최근 30일과 정확한 시작·종료일 표시 |
| 처리 시간·백분위·수락률 등 서로 다른 모집단의 수치가 과다 노출 | 접수·완료·담당자 수락 비율에 집중하고 분모와 기준 표시 |
| 따로 표시된 차트의 비교가 어려움 | 접수와 완료를 동일 축의 일별 막대로 비교, 날짜 선택과 수치 표 제공 |
| 고객 신고액을 실제 정산·입금 금액으로 오인할 수 있음 | ‘고객이 신고한 작업 금액’으로 명시하고 입력 설문 수·평균·신고 원본 이동 제공 |
| 공급·수요·압력·경보·좌표·출동 현황이 한 지도에 혼재 | 최근 30일 지역별 접수와 담당 지역 등록에 집중 |
| 접수 없는 지역이 목록을 채움 | 접수 발생 지역을 기본 표시, 전체/담당 등록 없음 필터와 이름 검색 추가 |
| 지도 색의 숫자 의미가 불명확 | 접수 건수로 색상을 통일하고 실제 건수 범위를 범례에 표시 |
| 작은 글자와 밀집된 레이아웃 | 큰 숫자, 명확한 제목·보조 설명, 정렬된 숫자 열과 여백 적용 |
| 모바일에서 지도 뒤에 지역 수치가 밀림 | 모바일·태블릿은 지역 목록을 먼저, 큰 화면은 지도와 목록을 나란히 배치 |

## 수치 정의

| 화면 항목 | 집계 기준 |
| --- | --- |
| 지금 남은 업무 | 전체 기간의 현재 RECEIVED + ASSIGNED + ACCEPTED + DISPATCHED. 완료·취소 제외 |
| 배정 대기 / 수락 대기 / 출동·작업 중 | 각 현재 상태. 클릭하면 해당 운영 큐 탭으로 이동 |
| 초긴급·긴급 | 현재 미완료 접수의 긴급도. 기존 메인 대시보드의 긴급 미완료 링크 유지 |
| 새 접수 | 선택 기간 createdAt 기준. 이후 취소된 건 포함 |
| 작업 완료 | 선택 기간 completedAt 기준. 이전 기간에 접수된 작업도 포함하므로 두 지표로 완료율을 만들지 않음 |
| 담당자 수락 비율 | 선택 기간 새 접수 중 조회 시점까지 ACCEPTED 배정 이력이 있는 접수 / 해당 기간 전체 새 접수. 분모 0이면 ‘집계 없음’ |
| 고객 신고 작업 금액 | 선택 기간 submittedAt 기준 설문의 paidAmount. 0원 포함, 미입력 제외. 실제 입금 확인액과 구분 |
| 지도 접수 | 오늘을 포함한 최근 30일 createdAt 기준, 취소 제외. 현황의 접수 지표와 취소 포함 기준이 다름을 명시 |
| 지도 담당 등록 | 해당 지역을 명시적으로 담당 지정한 활성·승인 업체 및 기사 수. 중복 등록 지역 간 합산은 전국 인원으로 쓸 수 없음 |
| 담당 등록 없음 | 접수는 있으나 담당 지역 등록 수가 0인 지역. 실제 배정 가능 여부를 단정하지 않음 |
| 위치 미확인 | 전국 단위 미확인 접수는 별도 안내. 시군구 확인 불가 건은 해당 시군구 목록 합계에서 제외 |

날짜는 한국 시간 기준이며 오늘을 포함합니다. 담당 지역 미지정 대상은 지도 등록 집계에서 제외됩니다. 실제 배정 후보는 알·계약·배정 규칙의 영향을 받으므로 지역 목록에서 순환 현황으로 연결합니다.

## 기능별 확인

- [x] 현재 업무와 선택 기간 실적의 수치·범위 분리
- [x] 오늘·7일·30일 전환 및 늦게 도착하는 이전 기간 응답 차단
- [x] 일별 막대 키보드 선택, 정확한 건수, 날짜별 표
- [x] 접수 0건·비율 미집계·금액 미입력에서 NaN/Infinity 없이 표현
- [x] 금액 입력 설문 수·평균과 정산 원본 링크
- [x] 접수 많은 순 정렬, 전체/접수 있음/담당 등록 없음 필터, 지역 검색
- [x] 접수 없는 지역을 담당 확보가 완료된 지역으로 오인하지 않는 안내
- [x] 전국 → 시군구 → 전국 이동, 세종 등 하위 구역 없는 지역의 후보 링크
- [x] 지도 키보드 접근과 갱신된 수치·범례·설명의 일치
- [x] 지역 API 실패 안내·재시도, 이전 성공 데이터 유지 시 명시
- [x] 지도 파일 없음·체크섬 불일치·비정상 JSON에서도 지역 목록 유지
- [x] 지도 로딩 실패 후 새로고침으로 재시도
- [x] 45초 지역 폴링 및 불필요한 출동 좌표 API 호출 제거
- [x] 관리자 인증·GET 전용 API·지역 입력 검증 유지
- [x] 320 / 390 / 768 / 1280 / 1440 / 1920px에서 페이지 가로 넘침 없음
- [x] 모바일 목록 우선 배치, 데스크톱 지도·목록 비율 및 서울 시군구 화면 직접 확인

## 검증 결과

- Next.js 프로덕션 빌드, TypeScript, 변경 파일 ESLint 통과.
- 집계 단위 테스트: analyticsStats / mapOverview / supplyDemand, 18개 통과.
- 현황·내비게이션·기존 폴링 브라우저 시나리오 22개 통과.
- 최종 지도·가독성·예외 상황 브라우저 시나리오 32개 통과.
- 390 / 768 / 1440px의 두 화면, 총 6회 접근성 자동 검사에서 지정 WCAG 규칙 위반 0건. 브라우저 예외 및 관리자 쓰기 요청 0건.
- 실제 지도 경계 17개 시도 및 서울 25개 시군구 확인.

검증은 격리된 로컬 DB와 콘솔 문자 환경에서 수행했습니다. 분석 집계 API와 정산·배정 업무 규칙은 변경하지 않았습니다. 기존 출동 API와 처리 성능 데이터는 유지하되 이 두 분석 화면의 기본 노출에서 제외했습니다.

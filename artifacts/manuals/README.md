## 수정과 재생성

본문의 원본은 `tools/manual-content.mjs`, 공통 서식은 `style.css`입니다. 생성된 HTML을 직접 수정하면 다음 빌드 때 덮어써집니다.

```sh
node artifacts/manuals/tools/build-manuals.mjs
node artifacts/manuals/render-pdf.mjs
```

첫 명령은 원고에서 참조하는 라이브 캡처의 존재, 출처 도메인, 개정 기준, SHA-256을 확인하고 HTML 8종과 `index.html`을 생성합니다. 두 번째 명령은 이미지·초안 여부를 확인한 뒤 목차 북마크와 페이지 번호가 있는 A4 PDF 8종을 생성합니다. 머리말의 날짜·버전도 공통 원고에서 가져옵니다.

초안 미리보기만 필요하면 첫 명령에 `--draft`를 붙일 수 있습니다. 초안은 PDF 생성 단계에서 거부됩니다.

## 라이브 캡처 갱신

촬영 기록은 `img/live-2026-09-10/capture.json`에 있습니다. URL, 촬영 시각, 화면 크기, 주석 좌표, 파일 해시를 기록하며 새 촬영분에는 스크롤 위치도 기록합니다.

`tools/capture-live.mjs`는 기존 촬영 목록을 유지하며 화면을 갱신합니다. 다음 환경변수를 사용합니다.

| 변수 | 용도 |
| --- | --- |
| `MANUAL_PUBLIC=1` | 공개 로그인·가입·고객 화면 |
| `MANUAL_ADMIN_STATE` | 관리자 로그인 상태 파일의 경로 |
| `MANUAL_PARTNER_STATE` | 업체 로그인 상태 파일의 경로 |
| `MANUAL_TECH_STATE` | 기사 로그인 상태 파일의 경로 |
| `MANUAL_CAPTURE_FILTER` | 다시 촬영할 작업 키, 쉼표로 구분 |

공개 접수 완료·설문 화면은 관리자 촬영이 남긴 기존 접수 목록을 사용합니다. 촬영 스크립트는 조회용 GET/HEAD와 고객 접수 조회 POST만 허용하며, 저장·배정·입금 처리·서명·설문 제출·문자 발송 요청은 차단합니다. 신규 접수나 계정을 만들지 않습니다. 현재 배정·계약서가 이미 완료된 계정은 그 상태로 촬영하며, 원고에서 상태별 버튼 차이를 설명합니다.

캡처·PDF·로그인 상태에는 운영 데이터가 포함될 수 있습니다. 캡처와 PDF는 기존 `.gitignore` 정책대로 로컬에 보관하고 로그인 상태 파일은 저장소 밖에 둡니다. 새 체크아웃에서는 별도 보관된 캡처를 가져오거나 다시 촬영한 후 PDF를 생성합니다.

개정 내용과 검증 범위는 [라이브 개정 기록](../../docs/manual-audit/라이브-개정-2026-09-10.md)을 참조하세요.
